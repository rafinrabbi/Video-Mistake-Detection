Here is the clean mental model of this project.

  Overall Goal

  This research system detects procedural mistakes in egocentric videos: “Is the person doing the right step, at the right time, with the right object/action?”

  The target dataset is EgoOops: 50 videos across 5 procedural tasks. Your local split is:

  train: 30 videos
  val:   10 videos
  test:  10 videos

  The main research idea has two parts:

  1. Procedural graph-guided VLM reasoning
     Instead of asking a vision-language model to judge a video blindly, the system gives it a structured task graph: expected steps, order, objects, states,
     and valid variations.
  2. Uncertainty-aware adaptive thresholding
     The model may be uncertain because of occlusion, ambiguous action, short clip, or weak graph match. The final decision threshold adapts using that
     uncertainty instead of using only a fixed confidence cutoff.

  Key docs: CLAUDE.md:1, plan.txt:1, pipeline_diagram.md:1.

  Step-By-Step Workflow

  1. Prepare EgoOops data

  The official EgoOops annotations are converted into this repo’s simpler format:

  clip_id
  task_id
  task_name
  task_description
  duration_sec
  mistakes: start_sec, end_sec, mistake_class

  Code: scripts/convert_egoops_annotations.py:1, src/vmd/data/egoops.py:1.

  Why this step matters: every later component needs a common format for loading videos, labels, task descriptions, and mistake timestamps.

  2. Split videos into clip windows

  Long videos are broken into small windows, default 4 seconds long with 2 second stride.

  Code: src/vmd/data/sampler.py:1.

  There are two protocols:

  online  = causal sliding windows, no future access
  offline = full video windows available for evaluation

  Why: online evaluation simulates real-time detection; offline evaluation measures performance when the full video can be processed.

  3. Build procedural graphs

  Each task description is converted into a graph:

  steps
  objects
  actions
  states
  edges

  Example edge:

  step_01 -> step_02, kind = after

  Code: src/vmd/graph/schema.py:1, src/vmd/graph/builder.py:1, src/vmd/graph/validator.py:1.

  Why: the graph gives the VLM procedural expectations. Without it, the model only sees video frames and lacks structured knowledge of what should happen next.

  Current local graphs:

  blacklight:   8 steps
  cardboard:   14 steps
  electronics: 8 steps
  ion:         9 steps
  tsumiki:     7 steps

  4. Prompt the VLM with video + graph context

  For each clip window, the system sends Qwen2.5-VL the sampled frames plus a prompt containing:

  task name
  current expected step
  valid next steps
  required objects
  expected states
  valid variations
  recent history

  Code: src/vmd/vlm/qwen25vl.py:1, src/vmd/vlm/prompts/reason.txt:1.

  The VLM must return JSON:

  {
    "deviation": true,
    "mistake_class": "wrong_object",
    "confidence": 0.82,
    "uncertainty_reason": "occlusion",
    "rationale": "...",
    "expected_vs_observed": "..."
  }

  Why: JSON makes the output measurable, comparable, and usable by later decision/evaluation code.

  5. Estimate uncertainty

  The system computes uncertainty from the VLM confidence and the reason it gives.

  Code: src/vmd/vlm/uncertainty.py:1.

  Formula idea:

  uncertainty = 0.6 * (1 - confidence) + 0.4 * reason_penalty

  Why: a high-confidence mistake prediction should be trusted more than a low-confidence one caused by occlusion or ambiguous action.

  6. Make the final decision

  The VLM says whether there is a deviation, but the decision layer decides whether to accept that prediction.

  Code: src/vmd/decision/threshold.py:1.

  Adaptive threshold uses:

  task complexity
  number of valid variants
  uncertainty
  graph confidence
  history inconsistency

  Why: procedural tasks are not equally hard. A fixed 0.5 threshold may be too strict for one task and too loose for another.

  Important current status: the code can fit adaptive threshold parameters with scripts/03b_fit_threshold.py:1, but scripts/04_full_eval.py:1 currently creates
  a default AdaptiveThreshold() instead of loading outputs/threshold_params.json.

  7. Postprocess over time

  Predictions are smoothed across neighboring windows.

  Code: src/vmd/decision/postprocess.py:1.

  Why: a single noisy clip should not cause a false mistake event. The system looks for stable mistake evidence across consecutive windows.

  8. Evaluate

  Metrics include:

  binary F1       = mistake vs no mistake
  macro F1        = mistake class quality
  AUC-ROC         = ranking quality of scores
  ECE / Brier     = calibration quality
  precision/recall

  Code: src/vmd/eval/metrics.py:1, src/vmd/eval/online.py:1, src/vmd/eval/offline.py:1.

  Current zero-shot validation result:

  online binary F1:  0.317
  offline binary F1: 0.324
  online macro F1:   0.200
  offline macro F1:  0.150

  Interpretation: the frozen VLM baseline works but is weak, especially for multiclass mistake type classification and calibration.
